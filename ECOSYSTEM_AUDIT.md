## 3. Рефлексия

### 3.1 Что сделано правильно

1. **Современный стек** — React 19, TypeScript strict, Vite 6
2. **AI-first подход** — Глубокая интеграция Gemini (чат, vision, TTS,
   генерация)
3. **Offline-first в APP** — IndexedDB + localStorage с fallback
4. **Монорепо структура** — npm workspaces с общей библиотекой
5. **PWA поддержка** — manifest.json, Service Worker, offline page
6. **Доступность** — Skip links, ARIA labels, focus states
7. **CI/CD** — GitHub Actions для lint, build, deploy
8. **Типизация** — 25+ интерфейсов в shared/types

### 3.2 Области для улучшения

1. **Безопасность** — API ключи exposed, нет валидации
2. **Тестирование** — Критически низкое покрытие (15%)
3. **Компоненты** — Слишком большие (ChatWidget 700 LOC)
4. **Аутентификация** — Нет реальной верификации
5. **Мониторинг** — Отсутствует отслеживание ошибок
6. **Монетизация** — Нет платёжной интеграции

### 3.3 Уроки

| Урок                                       | Применение                         |
| ------------------------------------------ | ---------------------------------- |
| "Один компонент — одна ответственность"    | Разбить ChatWidget на 4 компонента |
| "Безопасность с первого дня"               | API proxy через Edge Functions     |
| "Тесты — это документация"                 | 70%+ покрытие критических путей    |
| "Offline-first не означает insecure-first" | Валидация на клиенте И сервере     |

## 7. Размышления "Что если?"

### 7.1 Сценарий A: AI-First Studio

> **Что если K Sebe станет первой полностью AI-персонализированной йога-студией
> в России?**

**Реализация:**

- Aria (AI) анализирует настроение пользователя перед практикой
- Генерирует уникальную последовательность асан
- Подбирает музыку под энергетику дня
- Голосовой коуч сопровождает практику в реальном времени
- Анализирует прогресс и адаптирует сложность

**Инвестиции:** Средние (уже есть Gemini интеграция) **Потенциал:** Высокий
(уникальное позиционирование) **Риски:** Зависимость от Gemini API, высокие API
costs

### 7.2 Сценарий B: Inside Flow Academy Russia

> **Что если создать русскоязычную сертификацию Inside Flow?**

**Реализация:**

- Партнёрство с Inside Yoga Academy (Young Ho Kim)
- Онлайн-курс для преподавателей (50 часов)
- Сертификация через K Sebe платформу
- Marketplace сертифицированных учителей

**Инвестиции:** Высокие (контент, партнёрство, юридические) **Потенциал:** Очень
высокий (recurring B2B revenue) **Риски:** Сложные переговоры, конкуренция

### 7.3 Сценарий C: Lifestyle Ecosystem

> **Что если расширить экосистему за пределы йоги?**

**Модули:**

- 🧘 Йога (текущее)
- 🍎 Mindful Eating (рецепты, калории)
- 😴 Sleep (треки для сна, Gemini-генерация)
- 🏃 Movement (утренние разминки)
- 🧠 Mental Health (журнал настроения, AI-терапия)

**Инвестиции:** Очень высокие (новый контент, экспертиза) **Потенциал:** Очень
высокий (larger TAM) **Риски:** Размытие бренда, ресурсы

### 7.4 Сценарий D: Freemium Scale

> **Что если выйти на 100K+ активных пользователей?**

**Стратегия:**

- Бесплатный AI-чат с Арией (без лимитов)
- 3 видео в неделю бесплатно
- Premium ($990/мес): всё + offline
- VIP ($2990/мес): + личные консультации с Катей

**Unit Economics:**

- CAC: ~$5 (органика + Instagram)
- LTV Premium: $5,940 (6 месяцев × $990)
- LTV/CAC: 1188 (отлично)

**Инвестиции:** Средние (маркетинг, инфраструктура) **Потенциал:** Высокий
**Риски:** Инфраструктура при scale, support

## 10. Детализированные шаги развития

### Фаза 0: Критические исправления (1-2 недели)

#### 0.1 Безопасность API

**Задача:** Перенести API ключи на backend

**Шаги:**

1. Создать Supabase Edge Function `gemini-proxy`
2. Переместить `GEMINI_API_KEY` в Supabase secrets (backend), оставить
   `VITE_GEMINI_API_KEY` только для локального демо (frontend)
3. Обновить `geminiService.ts` для вызова Edge Function
4. Добавить rate limiting по user_id

**Файлы:**

```
supabase/functions/gemini-proxy/index.ts (новый)
k-sebe-yoga-studioWEB/services/geminiService.ts (обновить)
k-sebe-yoga-studio-APPp/services/geminiService.ts (обновить)
```

#### 0.2 XSS защита

**Задача:** Усилить DOMPurify конфигурацию

**Шаги:**

1. Добавить DOMPurify-санитизацию в WEB/APP Blog (как уже сделано в shared Blog)
2. Создать `sanitizeHtml` utility в shared
3. Применить ко всем dangerouslySetInnerHTML

#### 0.3 PWA Assets

**Задача:** Добавить недостающие иконки

**Шаги:**
